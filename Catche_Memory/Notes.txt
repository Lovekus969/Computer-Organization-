Catche Memory Cache Memory is:

A small but very fast memory located between the CPU and main memory (RAM).

It stores frequently accessed instructions and data so the CPU doesn’t have to fetch them repeatedly from the slower main memory.

Access speed of cache is close to CPU registers, much faster than RAM.

It is more expensive than main memory, which is why only a small amount is used.


ache Levels (L1, L2, L3):

L1 Cache
        
        Closest to the CPU core
        
        Smallest in size (usually 32KB–128KB)
        
        Fastest (almost as fast as CPU registers)
        
        Stores the most frequently used instructions/data

L2 Cache
        
        Larger (usually 256KB–1MB)
        
        Slightly slower than L1
        
        Acts as a backup for L1 cache

L3 Cache
        
        Much larger (can be 4MB–64MB)
        
        Slower compared to L1 & L2, but still faster than main memory (RAM)

Shared among multiple CPU cores


        5.1 Cache Memory Principles
                Why caches exist: Because there’s a large gap between the speed of fast, expensive memory (like SRAM, near CPU) and slower, cheaper large memory (main                      memory / DRAM). A cache is a small, fast memory that holds copies of portions of main memory to reduce average access time. 

Principle of locality:

        Temporal locality: recently used data is likely to be used again soon.
        Spatial locality: data near recently used data is likely to be used soon.

Cache and virtual memory interactions: Decisions about using physical vs. virtual addresses for caches (logical cache vs. physical cache), and where the cache sits relative to the MMU. 



                                                        Chapter 5.2: Elements of Cache Design

1. Mapping Function
                        Definition: Determines where a block of main memory can be placed in the cache.

🧩 Types:
                
                Direct-mapped – Each memory block maps to exactly one cache line.
                
                Advantage: Simple, fast lookup.
                
                Disadvantage: High conflict misses if many blocks map to the same line.
                
                Example: (Block address) mod (Number of cache lines)
        Q “What kind of miss increases most in a direct-mapped cache?” → Conflict misses?
                In a direct-mapped cache, each memory block can map to exactly one cache line.
        
        So the type of miss that increases most is:
                👉 Conflict misses
        
        Explanation:          
                        Conflict miss (also called collision miss) occurs when multiple blocks compete for the same cache line, even though other lines are free.
                        In a direct-mapped cache, this happens frequently because each block has only one possible location.
        
        Comparison:
        | Cache Type            | Miss Type Most Affected                                     |
        | --------------------- | ----------------------------------------------------------- |
        | **Direct-mapped**     | ✅ Conflict misses                                           |
        | **Fully associative** | ❌ No conflict misses (any block can go anywhere)            |
        | **Set-associative**   | ⚖️ Fewer conflict misses (more flexible than direct-mapped) |

2. Fully associative – Any block can go anywhere in cache.

        Advantage: Lowest conflict misses.
        Disadvantage: Expensive hardware (needs parallel tag comparison).
        
FAANG Q: “Why are fully associative caches rare in L1 caches?” → Cost and complexity.
 Fully associative caches are rare in L1 caches because of their high cost and hardware complexity.
        Here’s a breakdown of why:
                💡 What happens in a fully associative cache:
                        Any memory block can go anywhere in the cache.
                                To find a block, the cache must compare the address tag against all entries simultaneously.

        ⚙️ Why this is expensive:
                        Requires many comparators – one for every cache line.
                        → That means parallel tag comparisons, which are hardware-intensive and consume power.

                Longer access time – checking all lines in parallel slows down lookup, which is bad for L1 caches that need very low latency (1–2 CPU cycles).
                Higher energy and area cost – the circuitry for full associativity makes the chip larger and hotter, which is inefficient at the L1 level.

 Therefore:

                L1 caches prioritize speed over flexibility → usually direct-mapped or 2- to 4-way set associative.
                Fully associative caches are more common in small, slower caches like the TLB or L2/L3 victim caches.

 Final Answer:
        Fully associative caches are rare in L1 caches because they are too costly and complex in hardware (they need many comparators and longer access time).


3 Set-associative – Middle ground; cache is divided into sets; each set has n lines (n-way associative).
        Example: 4-way associative → each block maps to one of several lines in that set.
                Advantage: Fewer conflict misses than direct-mapped, less costly than fully associative.
                        FAANG Q: “What happens to hit rate as associativity increases?” → It improves but with diminishing returns.
        As associativity increases, the cache hit rate improves, but with diminishing returns.

🧠 Here’s why:

        Higher associativity → each memory block has more possible places to be stored.
        → This reduces conflict misses, since fewer blocks compete for the same line.
        → Therefore, hit rate goes up.

        ⚖️ But — diminishing returns:

        Going from direct-mapped → 2-way gives a big improvement.
        From 2-way → 4-way, smaller gain.
        Beyond 8-way or 16-way, the improvement is tiny, but the access time, power, and cost keep increasing.

                | Associativity         | Hit Rate                 | Hardware Cost | Access Time     |
                | --------------------- | ------------------------ | ------------- | --------------- |
                | Direct-mapped (1-way) | Low                      | Low           | Fast            |
                | 2-way                 | Higher                   | Moderate      | Slightly slower |
                | 4-way                 | High                     | High          | Slower          |
                | Fully associative     | Highest (but marginally) | Very high     | Slowest         |
Ans. As associativity increases, the hit rate improves, but with diminishing returns due to increasing complexity and slower access time.

Hit rate = the fraction (or percentage) of memory accesses that are found in the cache.

                Formally:         Hit Rate =          Total Memory Accesses / Number of Cache Hits
Conceptually
                When the CPU requests data:
                                If the data is already in the cache, ✅ → cache hit
                                If the data is not in the cache, ❌ → cache miss (data must be fetched from main memory)
                The hit rate measures how often the cache provides data directly without going to main memory.
	​
How to Increase Hit Rate

				Increase cache size → fewer capacity misses
				Increase associativity → fewer conflict misses
				Use appropriate block size → leverage spatial locality
				Good replacement policy (LRU, pseudo-LRU) → keeps useful data
				Multi-level caches → L2/L3 improve effective hit rate

Number of Caches
When caches were originally introduced, the typical system had a single cache. More
recently, the use of multiple caches has become the norm. Two aspects of this design
issue concern the number of levels of caches and the use of unified versus split caches.

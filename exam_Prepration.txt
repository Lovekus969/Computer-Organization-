1.What is the difference between computer organization and architecture?
Computer Architecture:

Computer architecture refers to the attributes of a computer system that are visible to the programmer and that have a direct impact on the logical execution of a program.
It includes the Instruction Set Architecture (ISA) — instruction formats, opcodes, registers, data types, memory addressing techniques, and the effect of instructions on registers and memory.

Computer Organization:

Computer organization refers to the operational units and their interconnections that implement the architectural specifications.
This includes hardware details such as the ALU, control signals, data paths, memory hierarchy, and how the CPU is internally structured.

 In Short:
  Architecture = WHAT the system does (programmer’s view)
  Organization = HOW the system is built (hardware implementation)

Q4. What is the difference between simple single processor computer and multicore computer structure?
 A simple single-processor computer has only one CPU core that executes one instruction stream at a time. A multicore computer contains multiple CPU cores on the same chip, allowing parallel execution of multiple instructions and higher performance.

Q5. What are major elements of a multicore computer? Define and explain how are they related to each other?
A multicore computer contains multiple CPU cores on the same chip, each with private L1/L2 caches, and all cores share an L3 cache, main memory, I/O subsystem, and an interconnect bus. A coherence mechanism maintains data consistency between cores when they access shared memory. All these components work together to enable parallel processing and faster system performance.

Q9. Define and explain the techniques used in contemporary processors to achieve speed-up.
   Contemporary processors include a number of techniques designed to increase instruction throughput and overall performance. The   main techniques are the following:
   1. Pipelining
   
   Pipelining breaks instruction execution into multiple stages (fetch, decode, fetch operands, execute, store result).
   The processor overlaps these operations so that multiple instructions are in different stages at the same time—similar to an assembly line.
   This increases throughput because while one instruction is executing, the next instruction is being decoded, and so on.
  2. Branch Prediction
  
  The processor looks ahead in the instruction stream and predicts which branch or sequence of instructions will be executed next.
  If the prediction is correct, the CPU fetches and buffers those instructions early, keeping the pipeline busy.
  Advanced predictors can look several branches ahead, increasing the amount of useful work available to execute.
  3. Superscalar Execution
  
  A superscalar processor is able to issue more than one instruction per clock cycle.
  It achieves this using multiple functional units and multiple parallel pipelines so several instructions can execute simultaneously.
  4. Data Flow Analysis
  
  The processor examines dependencies between instructions (results and operands) to create an optimized schedule.
  Instructions are executed as soon as their data is ready, independent of their original program order.
  This reduces stalls and improves parallelism.
  
  5. Speculative Execution
  
  Using branch prediction and data flow analysis, the processor executes instructions ahead of time, before it is certain they are needed.
  These results are kept in temporary storage until the branch outcome is verified.
  This keeps execution units busy by executing likely-needed instructions
 Q10. What changes have been introduced to balance the performance of memory with increasing microprocessor speeds?
 As microprocessor speeds increased much faster than memory speeds, several architectural changes were introduced to reduce the “memory wall” problem. The most important improvements are:
 1.	Cache Memory Hierarchy (L1, L2, L3):
 Fast caches store frequently used data close to the CPU, reducing slow RAM accesses.
 2.	Memory Interleaving:
 Main memory is divided into multiple banks that can be accessed in parallel, increasing overall bandwidth.
 3.	Faster and Wider Memory Technologies:
 Development of DDR/DDR5 RAM, wider buses, and higher clock speeds improves data transfer rates.
 4.	On-Chip Memory Controllers:
 Integrating the memory controller inside the CPU reduces latency and speeds up communication with RAM.

Q11. Discuss the challenges of Power, RC Delay and Memory Latency?
  Modern processors face three main challenges: power, RC delay, and memory latency. As processors get faster, they use more power and produce more heat, which makes it difficult to keep increasing speed safely. RC delay happens because the tiny wires inside the chip become thinner as technology shrinks, which slows down the movement of signals inside the processor. Memory latency (Time it takes to read something from the memory) is another problem because the CPU is very fast, but the main memory (RAM) is much slower, so the processor often has to wait for data, reducing overall performance. These three issues make it harder to improve processor speed and efficiency.

Q12. What is the difference between Multicore Processors and Graphics Processing Units?
  Multicore processors are CPUs that contain several general-purpose cores designed to run normal computer tasks like operating systems, applications, and multiple programs at the same time. They focus on fast decision-making, logic operations, and running a few complex tasks efficiently. In contrast, Graphics Processing Units (GPUs) have hundreds or thousands of small cores designed mainly for handling graphics, images, and large amounts of simple, repeated calculations in parallel. CPUs are good for complex tasks with a few threads, while GPUs are good for highly parallel work like gaming, AI, and scientific simulations

   Q14. Why hardwired software is more efficient than general purpose computers running a software?
Hardwired systems are built using fixed, dedicated electronic circuits to perform a specific task. Because the hardware is designed only for that one function, it can execute operations much faster, with less overhead and lower power consumption. In general-purpose computers, the CPU must fetch instructions, decode them, and run them through several layers of software, which takes extra time. Hardwired control directly performs the operation without this instruction-processing cycle. Therefore, hardwired systems are faster, simpler, and more efficient for a single dedicated task, while general-purpose computers trade speed for flexibility.

Q18. What is the difference between sequential interrupt processing and nested interrupt processing?
Difference Between Sequential Interrupt Processing and Nested Interrupt Processing
Sequential Interrupt Processing
•	In sequential interrupt processing, only one interrupt is handled at a time.
•	When an interrupt occurs, the CPU disables all other interrupts until the current interrupt service routine (ISR) is finished.
•	Other interrupts must wait in a queue.
•	This method is simple but can cause delays if a high-priority interrupt must wait for a low-priority one to complete.
________________________________________
Nested Interrupt Processing
•	In nested interrupt processing, the CPU allows higher-priority interrupts to interrupt a lower-priority interrupt handler.
•	When a new, higher-priority interrupt occurs, the processor pauses the current ISR, handles the new one, and then returns to the previous ISR.
•	This allows faster response to important interrupts.
•	It requires hardware support and more complex interrupt handling.

Q24. Point-to-point interconnection method is the faster way to connect various components. Explain the disadvantages of this method?
Disadvantages of Point-to-Point Interconnection
Although point-to-point interconnection provides fast and direct communication between components, it has several disadvantages:
	High Cost:
o	Each device requires a dedicated connection to every other device, which increases hardware cost significantly.
	Complex Wiring:
o	The number of wires grows rapidly with the number of devices, leading to complex and bulky wiring that is difficult to manage.
	Scalability Issues:
o	Adding a new device requires new dedicated connections to all other devices, making the system difficult to expand.
	Limited Flexibility:
o	Any change in the system configuration requires rewiring or redesigning the connections.

Q25. What is the difference between the link layer and routing layer in QPI four-layer architecture?
In the QPI four-layer architecture, the Link Layer ensures reliable data transfer between two directly connected devices by handling error detection, framing, and flow control. In contrast, the Routing Layer is responsible for forwarding packets across multiple nodes in the QPI network, determining the best path and managing addressing and switching. Simply put, the Link Layer focuses on data integrity on a single link, while the Routing Layer focuses on data delivery across the entire network.

Q26. What is the purpose of a switch in a typical PCIe configuration?
Purpose of a Switch in a PCIe Configuration
In a typical PCIe (Peripheral Component Interconnect Express) system, a switch is used to expand the number of PCIe devices that can be connected to the processor or root complex.
Functions of a PCIe Switch:
	Multiple Device Support:
o	Allows one PCIe root port to connect to several endpoints (graphics cards, SSDs, network cards) simultaneously.
	Packet Routing:
o	Receives packets from the root complex and forwards them to the correct downstream device.
	Bandwidth Management:
o	Shares the available PCIe lanes efficiently among multiple devices.
	Transparency:
o	Devices connected through the switch appear as if directly connected to the root complex.
Summary:
A PCIe switch increases connectivity, manages traffic, and enables multiple devices to communicate efficiently over PCIe lanes.

Q29. Studies have shown that the data address probability distribution is wider than the instruction address probability distribution, what does this mean?
	Studies show that the data address probability distribution is wider than the instruction address distribution, which means that programs tend to execute a small set of instructions repeatedly (narrow distribution), while data accesses are spread over many memory locations (wide distribution). As a result, instruction caches can be smaller and still effective, whereas data caches need to be larger or more sophisticated to handle the wider range of data addresses efficiently.
Q30. With the recent advances in big data, is spatial locality more important than temporal locality? Explain your answer.
Spatial locality has become more important in big data applications because large datasets are often processed sequentially or in blocks. Accessing contiguous memory regions allows efficient prefetching and better cache utilization. Temporal locality is still useful, but in big data, the sheer volume of data makes predictable sequential access (spatial locality) more critical for performance.

Q33. Why is associative access method more complex to design?
Associative (or fully associative) memory allows any memory block to be placed in any location, requiring the hardware to compare the input address with all stored addresses simultaneously. This parallel comparison logic is complex, costly, and consumes more power, making the design challenging.
Q34. What is transfer rate for a memory system and why is the calculation method different for random access and non-random access methods?
	Transfer Rate: Amount of data transferred per unit time (e.g., MB/s).
	Random Access Memory (RAM): Access time is uniform, so transfer rate is calculated as data size ÷ access time.
	Non-Random Access Memory (e.g., tapes, disks): Access time depends on seek, rotation, and latency, so transfer rate considers average access time plus data transfer time.

Q36.   Why L1 cache is smaller than L2 cache, L2 cache is smaller than L3 cache and so on?
•	Proximity vs Size Trade-off: Smaller caches are faster and placed closer to the CPU (L1) for quick access.
•	Larger caches (L2, L3) store more data but are slower and placed farther from the CPU.
•	This balances speed, cost, and capacity in a memory hierarchy.

Q37. What is the design principle of inclusion in memory systems?
•	Inclusion Principle: Data in a higher-level cache (L1) is also present in lower-level caches (L2, L3).
•	Ensures coherence, simplifies cache management, and makes it easier to invalidate blocks in lower caches when needed.

Q38. Which memory devices use vertical coherence, and which ones use hierarchical coherence?
	Vertical Coherence: Maintains consistency between different levels of cache and main memory (e.g., L1 ↔ L2 ↔ main memory).
	Hierarchical Coherence: Maintains consistency within caches at the same level across multiple processors (e.g., L1 caches in a multi-core CPU).

Q . What Is Direct Mapping?

Direct Mapping is the simplest cache-mapping technique.
	It defines a fixed rule telling where each block of main memory must go in the cache.
	
	👉 Formula used:
	
	The cache line is selected using the modulus operation:
	
					Cache Line Number=(Block Number)mod(Number of Cache Lines)
	  A single large cache would increase latency for most accesses, reducing CPU performance.

That means:
		
		Every memory block has only one exact position where it can be placed in cache.
		
		If two blocks map to the same cache line, they will replace each other.
	How Direct Mapping Works

		Memory address is divided into:
		Tag
		
					Index (decides which cache line)
					Offset (inside block)
		
		Example:
		If cache has 8 lines → index = block_number mod 8
					
					Block 0 → line 0
					
					Block 8 → line 0
					
					Block 16 → line 0


Why Can Associative Mapping Leave Free Space in Cache?
	✔ Because in fully associative mapping,
	a block can go ANYWHERE in the cache.
	
There are no fixed rules like “this block must go to line 5”.

So what happens?
		
		When the CPU loads memory blocks:
		It may fill some cache lines.
		Other lines may still be empty, because no mapping rule forces blocks to use those lines.
		
		In direct mapping, all blocks fighting for the same index fill the same line — so nothing stays “free”.
		
		But in fully associative mapping, the replacement algorithm (like LRU or FIFO) decides which line to use, and some lines might not get touched yet.
			
			. FIFO vs LRU — Which Is Faster?
		
		| Algorithm | Speed           | Miss Rate            | Which is better?                 |
		| --------- | --------------- | -------------------- | -------------------------------- |
		| **FIFO**  | Fastest         | Medium               | Simple hardware, quick decisions |
		| **LRU**   | Slightly slower | Best (lowest misses) | Acts closest to "real" usage     |
		
		FIFO is faster
		      because it only tracks the order of entry.
		
		✔ LRU is smarter
		      because it keeps the most recently used items.


Q.If RAM is slow and write-through writes to both cache and RAM, then what is the purpose of cache?
Doesn’t writing to RAM make the CPU wait?
With Write-Through, CPU Does NOT Wait for RAM

Ans:--> When using write-through, the CPU:

		Writes to cache
		Sends write request to RAM
		Immediately continues execution
		It does not wait for RAM to finish the slow write.

Why?
Because write-through often uses a Write Buffer (a small queue between cache and RAM).
. Write Buffer (VERY IMPORTANT)

When cache updates RAM, the write goes into a buffer, like a mini-queue.
	CPU → Cache → Write Buffer → RAM

So:
	
	Cache is updated instantly
	CPU keeps running
	Write buffer slowly writes to RAM in background
	
	👉 This is why write-through still works fast.

     Write-Through vs Write-Back (important comparison)

| Feature      | Write-Through         | Write-Back              |
| ------------ | --------------------- | ----------------------- |
| Write to RAM | Every write           | Only when block evicted |
| Speed        | Medium (buffer helps) | Fastest                 |
| Consistency  | High                  | Needs dirty bit         |
| Hardware     | Simple                | More complex            |

Write-through updates both cache and RAM, but CPU does not wait for slow RAM.
Write-through uses a write buffer that stores the write request and completes it in the background.
Cache still gives fast access for reads, and consistency is maintained between cache and memory.

Raid - Redundant Array of Independent Disks
RAID Level 0 (Disk Striping)

RAID 0, also called disk striping, splits data into blocks and distributes (stripes) them evenly across multiple disks.
This allows simultaneous read and write operations, greatly improving performance and storage capacity.

However, RAID 0 provides no redundancy — meaning there is no duplicate data stored to recover from a disk failure.
If one disk fails, all data is lost because parts of each file are spread across all disks.

Why RAID 0 is not a true RAID level

RAID stands for Redundant Array of Independent Disks, and RAID 0 does not provide redundancy.
Therefore, it improves performance only, not reliability, which is why it is not considered a “true” RAID level.

  RAID 0 uses data striping across disks to increase performance and capacity, but it lacks fault tolerance or redundancy. Hence, it is not a true member of the RAID family because it offers no data protection.

 RAID Level 1 (Disk Mirroring)
  
  RAID 1 provides redundancy through duplication rather than parity.
  In this scheme, all data is duplicated (mirrored) onto a second disk. Every write operation is performed simultaneously on two disks, so each disk contains an exact copy of the data.
  
  Like RAID 0, RAID 1 can use data striping, but each logical block is written to two physical disks — a primary and its mirror.
  If one disk fails, the system can continue operating using the mirror disk without data loss, ensuring high reliability and fault tolerance.

RAID Level 2 (Hamming Code ECC)
    
    RAID 2 uses bit-level striping across multiple disks and employs Hamming code for error detection and correction.
    In this scheme, data bits are distributed across several disks, and additional disks are used to store error-correcting codes (ECC) generated by the Hamming code algorithm.
    
    If a disk fails, the missing data can be reconstructed using the Hamming code stored on the parity (ECC) disks.
    This provides very high reliability and fault tolerance, as Hamming code can detect and correct single-bit errors and detect double-bit errors.

RAID Level 3 (Byte-level Striping with Interleaved Parity)

    RAID 3 uses byte-level striping across multiple disks and stores parity information on a separate dedicated disk.
    The parity bits are interleaved with the data so that for each set of data bytes written across the data disks, a parity byte is computed and stored on the parity disk.
    
    If one disk fails, the missing data can be reconstructed using the parity information and the remaining data disks.
    All disks operate synchronously, meaning every read or write involves all disks in the array.

RAID Level 4 (Block-level Striping with Dedicated Parity)

    RAID 4 organizes data into blocks (not bytes) and distributes these blocks across multiple disks — this is called block-level striping.
    A separate dedicated parity disk stores the parity information for each corresponding block stripe.
    
    When data is written, the parity for that block stripe is calculated using XOR operations and stored on the parity disk.
    If any single disk fails, the missing data can be reconstructed using the parity information and the remaining data blocks.
